# LTS Phase 5 — TPV104-200m results (jobs 52340525, 52344266)

**Date:** 2026-07-21 · **Branch:** `safs-v4_0_0-alt-case1-mfem-speed` · **Machine:** SDSC Expanse

## Summary — read this first

**What ran.** Clustered-LTS `seas_spatial_dyn_driver` vs its global-timestep (GTS) baseline, on
the SCEC TPV104 200 m production mesh (2,464,689 tets), p3 / ADER-O4, pure upwind, 256 ranks
(2 nodes × 128), fault-half interleave ON, to t = 2.0 s. Two runs: `cfl = 0.25` (52340525, LTS
only + a canceled GTS 52332649) and the **matched `cfl = 0.5`** pair (52344266, both legs) that
steps at exactly SeisSol's Courant number.

**Speed.** LTS is **1.48× faster than GTS** — against an **ideal ceiling of 3.68×** for this
(near-uniform) mesh, i.e. **~40 % of the theoretical LTS gain is realized net.** The ratio is
identical at both cfl (1.47× / 1.48×), confirming it is a real machinery property, not a dt artifact.

**The reframe — LTS *compute* already works; the loss is entirely exposed communication.**
Decomposing the matched run against GTS's measured compute floor:
- **LTS compute is 3.21× faster than GTS compute = 87 % of the 3.68× ceiling.** The element-update
  reduction delivers almost exactly what theory promises.
- The net collapses to 1.48× **only because 53 % of LTS wall is `MPI_Waitall`** — ghost-exchange
  completion waits sitting *exposed* on the critical path, on top of that fast compute.

**The contrast that proves it.** Same physics, same mesh, same 256 ranks: **GTS spends 0.00002 %
of wall in `MPI_Waitall` (2,682 calls); LTS spends 53 % (17–35 M calls).** The communication
explosion is 100 % an LTS-tick-loop artifact — not the mesh, not the partition, not baseline MPI.

**Physics.** ✅ **Validated at active rupture, both cfl.** V_max peaks ~17.3 m/s at t ≈ 1.48 s,
matching the GTS trace; nucleation at t ≈ 1.0–1.1 s, propagation, identical between cfl=0.25 and
cfl=0.5. First at-scale confirmation of the np=256 fault-half interleave under full slip. **cfl=0.5
is stable** — the stability gate is passed; 0.25 was inherited conservatism.

**Bottom line.** Phase 5's verdict is not "LTS underperforms" — it is **"LTS compute realizes 87 %
of ceiling; the entire shortfall is exposed comm, which is a known-fixable Phase-6 lever."**
Hiding + reducing the exchange projects to **~3.2× realized (~87 % net)**.

| region | **GTS** Time % | **GTS** calls | **LTS** Time % | **LTS** calls |

| **`MPI_Waitall`** | **0.00002 %** | **2,682** | **52.538 %** | **17,346,090** |
| `MPI_Allreduce` | 0.0024 % | 8,960 | 0.749 % | 88,064 |
| `MPI_Comm_dup` | — | 256 | 0.304 % | 256 |

| balance | `step` Max/Avg **1.0000** | | `Waitall` Max/Avg **1.72** | |

**Reading it:**
- **GTS is compute-bound and balanced to four nines** (`step` Max/Avg = 1.0000, all MPI ≈ 0.1 %).
  The mesh, partition, and ADER kernels are healthy — GTS extracts full throughput.
- **LTS `MPI_Waitall` = 53 % of wall**, and the injection (`Isend`/`Irecv`) is cheap — the cost is
  the *blocking wait*, i.e. the exchange is on the critical path and does **not** overlap compute.
- **~13,000× more `Waitall` calls than GTS** (17.3 M vs 2,682) and 585 M point-to-point messages —
  the LTS tick loop does ~125 predict+correct exchange rounds per sync (~64 `Waitall`/rank/sync).
  Entirely LTS-structural; GTS on the same mesh does one cheap exchange per step.
- **`Waitall` Max/Avg = 1.72** — real *wait-time* skew on top of a balanced *partition* (1.16):
  ranks idle 1.7× the average at the tick barriers. Communication/sync skew, not element imbalance.
- Message/`Waitall` counts halve exactly cfl=0.25 → 0.5 (34.7 M→17.3 M, 1.17 B→585 M) = half the
  syncs; the *fractions* are cfl-invariant (`Waitall` 53.0 % → 52.5 %).

## 4. Compute-vs-comm decomposition (the reframe, measured)

Matched cfl=0.5, per sim-s:

| | s / sim-s | note |
|---|---:|---|
| GTS total (≈ all compute) | **6465** | Max/Avg 1.0000 |
| LTS total | 4356 | net 1.48× |
| — LTS communication | 2341 | `Waitall` 2290 + Allreduce/Comm_dup/send/recv |
| — LTS compute | **2015** | ← **6465 / 2015 = 3.21× vs GTS compute** |

**LTS compute realizes 3.21× = 87 % of the 3.68× ceiling.** The remaining ~13 % is LTS per-update
overhead (the λ=0.63 wiggle created an 888-cell finest cluster that forces the 32-tick cadence).

**What the fix buys (projection):**
- *Overlap comm with compute* → LTS wall → max(compute 2015, comm 2341) = 2341 (comm-bound) →
  **6465/2341 = 2.76×**.
- *Overlap **and** reduce rounds ~4×* (comm 2341 → ~585) → wall → max(2015, 585) = 2015
  (compute-bound) → **6465/2015 = 3.21×**, i.e. **~87 % net realization** — near the ceiling.

## 6. Next levers (Phase-6 perf, ranked by the attribution)

1. **Reduce exchange rounds (biggest win).** Merge per-predict/per-correct exchanges into
   **per-tick** (≈125 → 32) and **cluster-mask** them (exchange only the clusters active at each
   tick). ~4× fewer messages/waits.
2. **Overlap comm with compute.** Post the ghost exchange before the independent compute so
   `MPI_Waitall` overlaps — SeisSol's communication-thread model. Alone → ~2.76×.
3. **Aggregate messages.** 585 M P2P messages is latency-bound; coalesce per-face into
   per-neighbor-rank sends.

Combined → **~3.21× realized (~87 %)**, backed by the *measured* 3.21× compute floor above.
