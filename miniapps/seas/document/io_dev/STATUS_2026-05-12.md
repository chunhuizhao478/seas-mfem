## What's done

### Phase 1–6 (pre-2026-05-12)

- VTKHDF + ZFP + HDF5 1.14 production output pipeline working end-to-end on Frontera.
- Build glue (`build_frontera.sh`):
  - HDF5 1.14.6 from source against intel/19 + impi/19 (Frontera's `phdf5/1.14.x` module is incompatible with intel-19).
  - ZFP 1.0.1 from source with `BIT_STREAM_WORD_SIZE=8` (required by H5Z-ZFP plugin).
  - H5Z-ZFP v1.1.1 from source.
  - gmsh 4.13.1 from source (Frontera ships no gmsh; the prebuilt Linux64 tarball needs glibc 2.23 and Frontera has 2.17).
  - `MFEM_USE_H5Z_ZFP=YES` added to `config/config.mk.in` template (was missing — silently caused the sbatch gate to fail).
- Sbatch updates across `jobs/{bp5,tpv102,tpv104,tpv205}/*phase6*.sbatch`:
  - Drop the phdf5 module load; use the from-source HDF5 / H5Z-ZFP via env vars.
  - Auto-detect `SEAS_MFEM_ROOT` by walking up from `$SLURM_SUBMIT_DIR` to find `build_frontera.sh`.
  - Regenerate the 200 m TPV `.msh` from `.geo` at submit time (the meshes are too large to commit).
  - TPV* sbatch upgraded from `--tfinal 5.0 / development / 02:00:00` to `--tfinal 12.0 / normal / 06:00:00`.
- Sync scripts at `jobs/{bp5,tpv102,tpv104}/sync_results.sh` for pulling `.vtkhdf + .dat` from Frontera to `~/Downloads/seas-mfem/<driver>/results_phase6_*` (mirrors cluster dir names).
- Output-size estimator wrapper `scripts/estimate_from_sbatch.py`:
  - Accepts an sbatch path; auto-resolves cadence/tolerance from the `ibrun` flags.
  - Auto-applies `--fault-tag 103` for TPV205 (its `.geo` uses 100-series tags).
  - Pretty terminal output (single-file vertical, multi-file aligned table, `--markdown` for docs, `--json` for piping).
- macOS ParaView setup: `install_name_tool` + `codesign --sign -` recipe documented in the walkthrough doc's "READ THIS FIRST" section to make the H5Z-ZFP plugin loadable on `ParaView-6.0.0-RC3.app` without segfaulting on the conda-vs-bundled-HDF5 conflict.

### Split-bulk-solutions refactor (2026-05-12, commits 7c16e62 onward)

- **Renamed** the three collection files for physical clarity:
  - `volume.vtkhdf` → `kinematics.vtkhdf`
  - `wave_bulk.vtkhdf` → `stress.vtkhdf`
  - `fault_surface.vtkhdf` → `fault.vtkhdf`
- **Split fields** to remove duplication:
  - `kinematics.vtkhdf` now holds only `velocity` + `mpi_rank` (TPV*) or `displacement` + `mpi_rank` (BP5).
  - `stress.vtkhdf` now holds the **full** symmetric stress tensor (6 components: σxx, σyy, σzz, σxy, σxz, σyz); previously only 3 were registered.
  - Velocity / mpi_rank no longer registered with `pv_bulk_out` — eliminates the byte-for-byte duplicate when cadence/tolerance matched.
- **Opt-in toggle for fault projections in kinematics**:
  - `SetRegisterFaultProjectionsInVolumePV(bool)` on `seas::ParaViewOutput`. Default `false`. Set `true` BEFORE `InitFaultOutputBP5(...)` to restore the pre-2026-05-12 behaviour where the 12 L2-p0 fault projections (`slip_dip`, `slip_strike`, `slip_rate_*`, `traction_*`, `state_variable`, `normal_stress`, `param_a`, `param_Dc`, `fault_x2`, `fault_x3`) are written into `kinematics.vtkhdf`. The GFs are always allocated; only the registration with `pv_dc_` is gated.

## Known caveats / sharp edges

- **HDF5 1.14.6 from source on Frontera is non-trivial.** intel/19 + impi/19 are required for ABI consistency with the rest of the build (hypre, mumps, petsc all pinned to intel-19). HDF5 builds in ~5 min on a login node.
- **gmsh from source on Frontera is non-trivial.** The system gcc/8.3 is used (Intel 19 ICEs on `untangle3d.cpp`). cmake needs `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` because gmsh's CMakeLists targets an old policy.
- **ZFP must be built with `BIT_STREAM_WORD_SIZE=8`.** Default (64) makes H5Z-ZFP refuse to apply the filter at runtime; symptom is `H5Dcreate2` failing with "I/O filters can't operate on this dataset" and the .vtkhdf file ending up at ~96 KB with no datasets.
- **macOS ParaView needs `install_name_tool` + ad-hoc codesign on the H5Z-ZFP plugin.** Otherwise it segfaults on launch (two HDF5 libs in one process) or gets killed by Gatekeeper. Walkthrough doc § "READ THIS FIRST" has the recipe.
- **TPV205's `.geo` uses 100-series physical tags** (not the 1/3/5 SCEC convention); the estimator wrapper auto-handles this. Direct estimator CLI use needs `--fault-tag 103`.
- **`make` warnings about `test-tpv104` duplicate recipe** are pre-existing and harmless (multiple Makefile blocks define the same target).

## How to resume work

1. Pull on Frontera:
   ```bash
   cd /scratch2/10024/zhaochun/seas-project/seas-mfem-paraview-compaction
   git pull
   bash build_frontera.sh        # QUICK=1 default; reuses extern/ caches
   ```
2. Submit a tpv102 dev job:
   ```bash
   sbatch miniapps/seas/jobs/tpv102/tpv102_phase6_paraview_zfp_dev_2hr.sbatch
   ```
3. Pull results locally (Mac):
   ```bash
   ~/projects/seas-mfem-paraview/miniapps/seas/jobs/tpv102/sync_results.sh
   ```
4. Open the result in ParaView (after the one-time macOS setup):
   ```bash
   paraview ~/Downloads/seas-mfem/tpv102/results_phase6_zfp_dev_job<N>/fault.vtkhdf &
   ```
