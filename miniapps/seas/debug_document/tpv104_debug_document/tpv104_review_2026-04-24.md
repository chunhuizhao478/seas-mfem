### [R-001] CRITICAL [slip_law_srw_psi.hpp:133-141] — Base-class `Rate` / `SteadyState` silently fall through to a default `V_w` (and default `a`), creating a class-design trap for Step 9

**Category:** BUG (silent wrong answer)

**Description:**
`SlipLawSRWPsi` inherits `StateEvolution` and overrides the base virtuals:
```cpp
real_t Rate(real_t V, real_t psi, real_t L) const override
{
   return Rate_SRW(V, psi, L, V_w_default_, a_);
}
real_t SteadyState(real_t V, real_t /*L*/) const override
{
   return SteadyState_SRW(V, V_w_default_, a_);
}
```
`V_w_default_` defaults to `1.0` in the constructor declaration
(`SlipLawSRWPsi(..., real_t V_w_default = 1.0)`), and `a_` is the single
scalar stored at construction. But the TPV104 design mandates **per-QP**
`V_w` (= 0.1 m/s inside the VW core, 1.0 m/s outside) and **per-QP**
`a` (= 0.01 inside VW, 0.02 outside). If the Step-9 driver (or any
future call site) uses the base-class virtual `law.Rate(V, psi, L)`
instead of the SRW-aware `law.Rate_SRW(V, psi, L, V_w[i], a[i])`, the
call silently uses the defaults — which means **every VW-core QP
receives the strengthening `V_w = 1.0` instead of `V_w = 0.1`**, and
every QP receives the global scalar `a_` (whatever was passed at
construction). Result: rupture never nucleates, ψ evolves toward the
wrong steady state, and the bug is silent (no compile error, no runtime
assert, smoke test still produces finite numbers).

**Trigger:** Step-9 driver wires an `StateEvolution*` base pointer (as
the ADER / RK4 pipeline currently does for `AgingLawPsi`/`SlipLawPsi`)
and calls `base->Rate(...)` without the TPV104-specific overload. Also
fires if `SlipLawSRWPsi law(...)` is constructed without the `V_w_default`
argument (uses `1.0` default).

**Actual behavior:** Silent fallback to `V_w_default_ = 1.0` and the
stored `a_` scalar. No assert, no warning.

**Expected behavior:** Either (a) the base virtuals abort with a loud
runtime error (`MFEM_ABORT` / `std::logic_error`) directing the caller
to the `_SRW` overloads, OR (b) the base virtuals are `= delete`d so a
misuse is a compile-time error.

**Suggested fix (option a — recommended, preserves StateEvolution
polymorphism for test fixtures that use uniform V_w):**
```diff
   real_t Rate(real_t V, real_t psi, real_t L) const override
   {
-     return Rate_SRW(V, psi, L, V_w_default_, a_);
+     MFEM_VERIFY(using_scalar_defaults_,
+                 "SlipLawSRWPsi::Rate base-virtual called without "
+                 "per-QP V_w / a.  Use Rate_SRW(V, psi, L, V_w[i], "
+                 "a[i]) in the production driver.");
+     return Rate_SRW(V, psi, L, V_w_default_, a_);
   }
   real_t SteadyState(real_t V, real_t /*L*/) const override
   {
-     return SteadyState_SRW(V, V_w_default_, a_);
+     MFEM_VERIFY(using_scalar_defaults_,
+                 "SlipLawSRWPsi::SteadyState base-virtual called "
+                 "without per-QP V_w / a.");
+     return SteadyState_SRW(V, V_w_default_, a_);
   }
```
Add a private `bool using_scalar_defaults_ = true;` that the driver
flips to `false` at construction before wiring into the ADER loop, and
that test fixtures (T_SRW_3, T_SRW_7) keep as `true`.

**Test case:**
```cpp
void test_R001_base_virtual_guarded() {
   SlipLawSRWPsi law(0.01, 0.014, 1e-6, 0.6, 0.1);  // V_w_default = 1.0
   law.SetProductionMode();     // flips using_scalar_defaults_ -> false

   // In production mode, calling the base virtual must abort.
   bool aborted = false;
   try { law.Rate(1e-6, 0.5, 0.4); }
   catch (const std::exception&) { aborted = true; }
   ASSERT_TRUE(aborted);

   // The SRW-aware overload must still work.
   const real_t r = law.Rate_SRW(1e-6, 0.5, 0.4,
                                 /*V_w=*/0.1, /*a=*/0.01);
   ASSERT_TRUE(std::isfinite(r));
}
```

### [R-002] CRITICAL [slip_law_srw_psi.hpp:74, 194] — `V_safe = max(V, 1e-45)` clamp silently diverges from SeisSol's `updateStateVariable`, which uses `V` unclamped

**Category:** BUG (silent divergence from SeisSol on the `V < 1e-45` branch)

**Description:**
Our `UpdateStateAnalyticSlipLawSRW` and `PsiSS_SRW` both clamp the
input slip rate:
```cpp
const real_t V_safe = std::max(V, static_cast<real_t>(1e-45));
const real_t f_LV = std::max(0, f0 - (b-a)*std::log(V_safe / V0));
// ...  V_safe used throughout
```
SeisSol's `FastVelocityWeakeningLaw::updateStateVariable` uses the
raw `localSlipRate` **without any clamp** (`FastVelocityWeakeningLaw.h:57-74`):
```cpp
this->f0[face][qp] - (this->b[face][qp] - localA)
                       * log(localSlipRate / this->drParameters->rsSr0)
```
For `V ∈ (0, 1e-45)` the two codes produce different `f_LV`, `psi_ss`,
and analytic-step results. Byte-match test T_SRW_5/T_SRW_8 (lines
205-296) draws `V ∈ [1e-18, 10]`, so the clamp **never fires in the
test**. The claimed "max-rel-err 0" tells us nothing about the clamp
branch.

**Trigger:** TPV104 simulation with sub-normal V (physically possible
during a Newton iteration that overshoots below 1e-45, or in a future
fixture that starts below it).

**Actual behavior:** Silent numerical divergence. For `V = 1e-48`:
- SeisSol: `log(V/V0) = log(1e-42) = -96.7`, `f_LV = 0.6 + (b-a)·96.7`.
- MFEM:    `log(V_safe/V0) = log(1e-39) = -89.8`, `f_LV = 0.6 + (b-a)·89.8`.

**Expected behavior:** Either (a) remove the clamp (SeisSol relies on
upstream clamping in the friction solver's `rs::almostZero()` floor),
OR (b) extend T_SRW_8's random draw to include `V < 1e-45` and
document the deliberate divergence.

**Suggested fix (option a — recommended, matches SeisSol):**
```diff
-   const real_t V_safe = std::max(V, static_cast<real_t>(1e-45));
-
-   const real_t f_LV = std::max(static_cast<real_t>(0),
-                                f0 - (b - a) * std::log(V_safe / V0));
+   // Match SeisSol: use raw V.  Upstream (friction solver Newton)
+   // clamps V >= rs::almostZero() = 1e-45, so log(V/V0) is finite
+   // on the production path.
+   const real_t f_LV = std::max(static_cast<real_t>(0),
+                                f0 - (b - a) * std::log(V / V0));
    ...
-   const real_t V_over_Vw = V_safe / V_w;
+   const real_t V_over_Vw = V / V_w;
    ...
-   const real_t psi_ss = a * LogSinh_SeisSol(2.0 * V0 / V_safe, f_ss / a);
+   const real_t psi_ss = a * LogSinh_SeisSol(2.0 * V0 / V, f_ss / a);
```
Apply the same edit inside `SlipLawSRWPsi::PsiSS_SRW` (line 194) and the
`Rate_SRW` helper.

**Test case:**

### [R-003] MODERATE [test_slip_law_srw_psi.cpp:205-296, test_tpv104_friction_solver_newton.cpp:119-191] — "SeisSol byte-match" tests compare against inline code that shares our helpers, producing a tautological zero diff

**Category:** ASSUMPTION (false confidence in claimed bit-match)

**Description:**
The T_SRW_5/T_SRW_8 and T_TPV104_FS_3 byte-match tests each define an
inline "SeisSol-verbatim" lambda that re-derives the SRW update / Newton
iteration. Inspection of those lambdas shows they duplicate our
production primitives, not SeisSol's live code:

- T_SRW_5/T_SRW_8 `seissol_update` lambda (line 211) reuses the
  `expm1(-2*absC)` form for `logsinh` — identical to our
  `LogSinh_SeisSol`. It also uses `std::pow(V/V_w, 8.0)` matching our
  header, whereas SeisSol uses the template integer power
  `misc::power<8, double>` which can be ULP-different.
- T_TPV104_FS_3 `seissol_newton` lambda (line 124) calls our
  `friction_seissol::FrictionCoefficientSeisSol` and
  `FrictionCoefficientSeisSolDerivV` inside its Newton body — so the
  "byte-match" is against a lambda that wraps our own helpers.

The claim "max-rel-err 0 on 1000-sample inline SeisSol FVW port" is
therefore a self-consistency check, not an independent cross-check
against SeisSol's live runtime. A future bug in `LogSinh_SeisSol`,
`ArsinhExp`, or `ComputeCExp` would appear in BOTH the production
header AND the test lambda, and the test would still report zero diff.

**Trigger:** Any regression in the shared primitives
(`LogSinh_SeisSol`, `ArsinhExp`, `ComputeCExp`) introduced by a future
refactor.

**Actual behavior:** T_SRW_5/T_SRW_8 and T_TPV104_FS_3 pass trivially
(max-rel-err 0) regardless of whether the shared primitives still
match SeisSol.

**Expected behavior:** The inline "reference" lambdas should be
**standalone** — inline the full arithmetic (exp, log, asinh, sqrt)
without calling any of our production helpers. That way a drift in the
production helpers is visible as a nonzero diff.

**Suggested fix (T_SRW_5/T_SRW_8 — rewrite the lambda to inline
primitives):**
```diff
 auto seissol_update = [](real_t psi_0, real_t V, real_t L, real_t dt,
                          real_t V_w, real_t a,
                          real_t b, real_t V0, real_t f0, real_t muW)
    -> real_t
 {
    const real_t lowVelocityFriction = std::max(
       static_cast<real_t>(0),
       f0 - (b - a) * std::log(V / V0));
-   const real_t steadyStateFrictionCoefficient =
-      muW + (lowVelocityFriction - muW)
-          / std::pow(1.0 + std::pow(V / V_w, 8.0), 1.0 / 8.0);
+   // Integer power: match SeisSol's misc::power<8, double> unrolled
+   // form  ((x*x)*(x*x)) * ((x*x)*(x*x)).
+   const real_t r  = V / V_w;
+   const real_t r2 = r  * r;
+   const real_t r4 = r2 * r2;
+   const real_t r8 = r4 * r4;
+   const real_t steadyStateFrictionCoefficient =
+      muW + (lowVelocityFriction - muW) / std::pow(1.0 + r8, 1.0/8.0);
    ...
 };
```
Similarly, T_TPV104_FS_3 should inline μ and dμ/dV instead of calling
our `friction_seissol::*` functions.

**Test case:** same test body; with an artificially broken
`LogSinh_SeisSol` (e.g. multiply return by 1.00001), the rewritten
lambda must flag a diff > 1e-13. Currently both production and test
return the same broken value so diff = 0.

### [R-004] MODERATE [slip_law_srw_psi.hpp:85, 202] — `std::pow(V_over_Vw, 8.0)` can ULP-drift from SeisSol's integer-power template

**Category:** BUG (ULP-level mismatch with SeisSol's live runtime)

**Description:**
SeisSol computes `(V/V_w)^8` via the compile-time unrolled template:
```cpp
std::pow(1.0 + misc::power<8, double>(localSlipRate / localSrW), 1.0 / 8.0);
```
where `misc::power<8, double>(x)` expands to chained multiplications
(typically `((x*x)*(x*x))*((x*x)*(x*x))`). Our header uses
`std::pow(V_over_Vw, 8.0)` — a library function typically implemented
via `exp(8*log(x))`, which has ~1–3 ULP error relative to the
multiplicative form. On the TPV104 envelope this difference is
small (well below 1e-13), but it **does** make the "byte-match"
claim of T_SRW_5/T_SRW_8 untrue against the real SeisSol build — it
is only true against our self-referencing lambda (see R-003).

**Trigger:** Any Phase-3 Frontera probe comparison against SeisSol's
real `updateStateVariable` output for `(V/V_w)` near the crossover
(V ≈ V_w = 0.1 m/s during nucleation, up to ≈ 1.0 m/s in breakout).

**Actual behavior:** ~1-3 ULP drift per evaluation, accumulated over
the ψ trajectory.

**Expected behavior:** Either inline the unrolled integer-8 power, or
document the `std::pow` drift explicitly so Probe 2 threshold is
calibrated accordingly (§5.10.2 currently asserts 1e-13).

**Suggested fix (preferred — match SeisSol's arithmetic exactly):**
```diff
    const real_t V_over_Vw   = V_safe / V_w;
-   const real_t V_over_Vw_8 = std::pow(V_over_Vw, static_cast<real_t>(8.0));
+   // Match SeisSol's misc::power<8, double>: ((x*x)*(x*x))*((x*x)*(x*x)).
+   const real_t r2 = V_over_Vw * V_over_Vw;
+   const real_t r4 = r2 * r2;
+   const real_t V_over_Vw_8 = r4 * r4;
    const real_t denom       = std::pow(1.0 + V_over_Vw_8,
                                        static_cast<real_t>(1.0 / 8.0));
```
Apply identically in `UpdateStateAnalyticSlipLawSRW` (line 85) and
`PsiSS_SRW` (line 202).

**Test case:**
```cpp
void test_R004_integer_power_matches() {
   // At V / V_w = 1.1 (near the transition in nucleation), std::pow
   // and the unrolled form differ by O(1 ULP).  After the fix, the
   // production result uses the unrolled form.
   const real_t V   = 0.11;
   const real_t Vw  = 0.1;
   const real_t r   = V / Vw;
   const real_t p_pow  = std::pow(r, 8.0);
   const real_t r2 = r*r, r4 = r2*r2;
   const real_t p_mul  = r4 * r4;
   // Confirm the two paths differ (otherwise std::pow is already
   // specialised and the fix is a no-op).
   ASSERT_NE(p_pow, p_mul);
}
```

### [R-005] MODERATE [friction_coeff_seissol.hpp:126] — `FrictionCoefficientSeisSol(V=0)` early-return is a silent divergence from SeisSol's `updateMu`, which has no V<=0 guard

**Category:** BUG (silent divergence from SeisSol at degenerate input)

**Description:**
Our port has:
```cpp
inline real_t FrictionCoefficientSeisSol(real_t V, real_t psi, real_t a,
                                         real_t V0)
{
   if (V <= 0.0) { return 0.0; }
   ...
}
```
SeisSol's `updateMu` (`FastVelocityWeakeningLaw.h:118-122`) has **no**
such guard — it feeds `V` through `arsinhexp` unconditionally. At
`V = 0` both code paths produce μ = 0 by algebraic identity (see
analysis in the class docstring). But at `V < 0` (possible as an
intermediate Newton iterate if a convergence step overshoots past zero
before the `std::max(rs::almostZero, V - g/dg)` clamp catches it), our
port returns 0, while SeisSol returns a negative μ via
`asinh(negative)`. The Newton residual `g = -(1/η_s)·(σ_n·μ − τ) − V`
is then different, and subsequent iterates diverge.

Moreover: the early return means our derivative companion
`FrictionCoefficientSeisSolDerivV(V=0)` returns `acLin * cExp` (normal
branch, x=0, v=0, return `acLin / sqrt(1)`) which is **non-zero**. So
at V=0, g = 0 / nonzero = 0 — OK. But at V slightly negative, μ = 0
(our port) while dμ/dV is positive (from SeisSol formula). The Newton
step would be `V - 0/dg = V` (step = 0, stall), not SeisSol's behavior.

**Trigger:** Newton iteration where an intermediate step lands at
`V ≤ 0` before the clamp catches it.

**Actual behavior:** μ early-returns 0 at V ≤ 0; derivative does not.
Asymmetric handling.

**Expected behavior:** No early return — match SeisSol exactly; rely on
the caller's `rs::almostZero` clamp. If paranoia about negative V is
warranted, assert V >= 0 at entry with a loud message.

**Suggested fix (match SeisSol):**
```diff
 inline real_t FrictionCoefficientSeisSol(real_t V, real_t psi, real_t a,
                                          real_t V0)
 {
-   if (V <= 0.0) { return 0.0; }
+   // SeisSol's updateMu has no V<=0 guard.  The caller (Newton solver)
+   // clamps V >= almostZero before dispatch.  If V <= 0 slips through,
+   // arsinhexp returns 0 at V=0 algebraically; at V<0, asinh returns
+   // negative, matching SeisSol's behavior.
    const real_t cLin    = 0.5 / V0;
    const real_t cExpLog = psi / a;
    ...
```

**Test case:**
```cpp
void test_R005_matches_seissol_at_zero_and_negative_V() {
   const real_t psi = 0.5, a = 0.01, V0 = 1e-6;
   // At V = 0: both codes return 0 (after fix).
   ASSERT_NEAR(FrictionCoefficientSeisSol( 0.0, psi, a, V0), 0.0, 1e-15);
   // At V < 0: SeisSol returns asinh(negative) = negative; our port
   // should match, not early-return 0.
   const real_t ours = FrictionCoefficientSeisSol(-1e-9, psi, a, V0);
   ASSERT_LT(ours, 0.0);
}
```

### [R-007] MODERATE [test_tpv104_friction_solver_newton.cpp:52] — T_TPV104_FS_1 initial guess `tau / (sigma_n * 0.6 + eta_s)` poisons Newton convergence at the low-τ end of the envelope

**Category:** EDGE_CASE (test design, produces noise instead of signal)

**Description:**
```cpp
const real_t V_guess = tau / (kSigmaN_TPV * 0.6 + kEta_TPV);
```
For the test envelope `tau ∈ [1e4, 1e8]`:
- at `tau = 1e4`: `V_guess = 1e4 / (72e6 + 4.6e6) ≈ 1.3e-4 m/s`.
- at `tau = 1e8`: `V_guess ≈ 1.3 m/s`.

The rest-state solution for `tau = 1e4, ψ = 0.5, σ_n = 120e6` is
`V ≈ 1e-32` (deep sub-normal); Newton starting from `V_0 = 1e-4` must
cross ~28 decades to find it. Newton in V-space converges locally;
crossing 28 decades requires many iterations, often more than
`max_iter = 60`. The test's `non_conv < N/100 = 50` tolerance then
hinges on how many of the 5000 random samples land in the low-τ regime.

**Trigger:** `tau ≤ 1e5` in the test's random draw.

**Actual behavior:** Test passes with the current RNG seed but the
non-convergence rate is a hidden function of the random draw.
Changing the seed could cause spurious test failures.

**Expected behavior:** Use a V_guess that is closer to the expected
root across the envelope. The SeisSol pattern is "previous-step V" —
use a physically reasonable prior that scales with τ.

**Suggested fix:**
```diff
-      const real_t V_guess = tau / (kSigmaN_TPV * 0.6 + kEta_TPV);
+      // Use a log-spaced guess matching rough physical expectation:
+      // τ = σ_n·μ(V) + η·V, for small V  τ ≈ σ_n·a·sinh((V/(2V₀))·exp(ψ/a)).
+      // Invert approximately via  V ≈ 2V₀·exp(−ψ/a)·sinh(τ/(σ_n·a)).
+      const real_t arg = tau / (kSigmaN_TPV * a);
```

### [R-009] LOW [tpv104_params.hpp:198-204] — `ComputeInitialPsiTPV104` uses `std::sinh(arg)` directly, overflowing at `arg > 709` (small-a regime)

### [R-010] LOW [test_slip_law_srw_psi.cpp:49-105] — T_SRW_1 random envelope can overflow the direct-formula reference (`sinh(f_ss/a) = inf`); current RNG seed hides it

**Category:** EDGE_CASE (test coverage robustness)

**Description:**
T_SRW_1 draws `V ∈ [1e-18, 10]`, `V_w ∈ [0.01, 10]`, `a ∈ [0.005, 0.04]`,
`b ∈ [0.006, 0.05]`, `muW ∈ [0, 0.3]`. At the worst corner
`(V = 1e-18, V_w = 10, a = 0.005, b = 0.05, muW = 0)`:
- `f_LV = max(0, 0.6 − 0.045 · log(1e-12)) = max(0, 0.6 + 1.24) = 1.84`
- `f_ss ≈ f_LV = 1.84` (since V/V_w ≈ 0)
- `f_ss / a = 368`, `sinh(368) = overflow → +inf`.

Direct-formula reference: `a * log(2V0/V · inf) = inf`. Our
`PsiSS_SRW` via `LogSinh_SeisSol` returns a finite value (`a * (absC +
log(...))`). `BothNonFinite(finite, inf) = false`; `rel = |finite −
inf|/inf = NaN`; `NaN < 1e-12` is false → test FAILS.

The current RNG seed (`20260424`) happens to not draw a sample that
hits this corner in 20 iterations (user reports 20/20 pass). A
different seed could flip the result, making the test flaky.

**Trigger:** RNG seed that draws a sample with `f_ss/a > ~700`.

**Actual behavior:** Test is seed-dependent.

**Expected behavior:** Either (a) restrict the envelope so `f_ss/a ≤
300` across all samples (safely below the `sinh` overflow at ~710), or
(b) use `LogSinh_SeisSol` on the reference side too, so both
computations compare at the same numerical form.

**Suggested fix (option a — narrow the envelope):**
```diff
    std::uniform_real_distribution<real_t> logV(-18.0, 1.0);
-   std::uniform_real_distribution<real_t> logVw(-2.0, 1.0);
-   std::uniform_real_distribution<real_t> aRng(0.005, 0.04);
-   std::uniform_real_distribution<real_t> bRng(0.006, 0.05);
-   std::uniform_real_distribution<real_t> fwRng(0.0, 0.3);
+   std::uniform_real_distribution<real_t> logVw(-1.0, 1.0);
+   std::uniform_real_distribution<real_t> aRng(0.008, 0.04);  // a ≥ 0.008 bounds f/a
+   std::uniform_real_distribution<real_t> bRng(0.006, 0.04);
+   std::uniform_real_distribution<real_t> fwRng(0.05, 0.3);
    // Post-draw guard: reject samples with f_ss/a > 300.
```
Or (b):
```diff
-   const real_t expected = a * std::log(2.0 * V0 / V_safe
-                                        * std::sinh(f_ss / a));
+   const real_t expected = a * LogSinh_SeisSol(2.0 * V0 / V_safe, f_ss / a);
```
Note: option (b) makes the "direct formula" reference lean on our own
`LogSinh_SeisSol`, weakening the test's independence (shares the same
concern as R-003). Prefer (a).
